# 2026-10-19 实车问题修复说明

本轮仅修改源码并进行编译、单元测试及静态检查，不生成或部署 APK。
保留工作区原有未提交修改，不更改版本号、认证材料或签名配置。

## 摄像头切换

- Activity 暂时退到后台时暂停视频解码，保留音频、USB/NCM 和 AirPlay 会话。
- 视频接收线程在不可见时降低优先级，仍继续读取、认证解密并推进 nonce；不把后台数据积压到 TCP 中。
- Surface/可见性变化立即停止旧解码任务，等待和释放在专用后台线程进行。
- 用切换代次防止快速切换时旧清理任务恢复新画面；旧解码线程实际退出后才允许创建新解码器。
- 返回前台按需请求关键帧，从新的参考帧链恢复。

这会降低后台解码及渲染压力，但不会消除认证解密本身的计算量。未替换密码实现或跳过认证。
前台仍有卡顿时，需要用新增解密 CPU/墙钟累计统计继续定位，不能宣称所有延迟已消除。

## 方向盘媒体按键

- 新增 API17 AudioManager 媒体按键注册、接收和前台按键统一分发。
- 标准上一曲、下一曲、播放、暂停、播放/暂停键转为 CarPlay 媒体 HID。
- 按下/释放报告在同一事件写锁内发送；记录实际发送结果。
- 对重复投递、长按重复进行过滤；有界队列避免控制消息无限积压。
- 会话结束撤销注册，排队事件不会转发到新会话；原厂音量键及方向键保持原行为。

尚无本田专用按键码或原厂私有控制接口证据，因此未猜测映射。若实车仍无法切歌，
检查 Hardware key、Unmapped media key 和 Media key sent 日志，判断是事件未到达还是报告发送失败。

## 导航音量

- 主页新增“导航音量”，提供原始、1.5 倍、2 倍、3 倍，保存选择，默认 1.5 倍。
- 仅 guidance/navigation 及旧式 type=101/default 提示流应用 PCM16 增益。
- 峰值限制统一作用于整个音频块，保持左右声道比例，防止放大后整数溢出或硬削波；不修改共享输入缓冲。
- 音乐、电话、Siri 和明确标记的 alert 不应用导航增益。
- 根据 AudioTrack 排队时长延长语音检测的衰减保持，避免播报尾音尚未播放完就恢复音乐。
- 音频日志增加用途分类、导航增益和输入峰值。

如果手机将导航与音乐预先混为一条 media 流，本轮不会对整条音乐流放大，也无法从中单独提高导航。
此情形需核对导航应用设置及流协商。type=101/default 本身没有明确用途，需实车确认其内容。

## 启动与诊断

- Auto 模式等待“已有原厂热点启动/地址准备”的单阶段超时改为 1 秒，失败后继续有线。
- 显式 Wi-Fi 测试模式保留原等待策略。
- 这不是完整的热点异步化；新建热点、Wi-Fi 关闭及恢复流程仍有各自超时。
- 恢复视频解密帧数、累计墙钟/线程 CPU、最大线程 CPU 统计，每个窗口独立重置。

## 实车验收

1. 对比原厂界面和 CarPlay 下，右转触发到 LaneWatch 首帧的时间；重复短切换与长时间覆盖。
2. 摄像头关闭后恢复当前 CarPlay 画面，连接和音乐不中断；检查热机后的最差延迟。
3. 前台、摄像头覆盖、USB 重连后分别按左右键；一次短按只切一首，音量键继续控制原厂音量。
4. 仅导航与导航加音乐分别测试，检查首字、尾音、增益设置、破音及音乐恢复。
5. 导航、音乐、摄像头、切歌联合运行至少 90 分钟。

单元测试不替代原厂摄像头、方向盘私有事件及扬声器实际响度验收。
