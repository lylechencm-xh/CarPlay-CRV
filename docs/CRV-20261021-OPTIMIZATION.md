# CR-V 音视频与连接状态优化（2026-10-21）

本轮只修改源码与测试，不生成、安装或发布 APK。保留原有 USB/NCM、MFi、包名、API17 和 ABI 基线；标准画面仍为 1280×720 / 最高 20fps。

## 实现范围

- 视频读取与认证/解密分线程；帧与配置进入同一个 FIFO，配置不能越过旧帧。接收队列最多保留 3 个待处理消息、通常最多 2MiB；单个协议允许的大消息可独占队列，另有正在处理和接收的消息。队列满时施加背压，不直接丢弃密文；每个加密视频消息分配且只使用一次 nonce。关闭唤醒读写双方，EOF 先排空已收到的消息，退出回调只发一次。
- 解密后才淘汰过期压缩帧。只有存在更新消息且帧龄超过 250ms 的非关键帧才会淘汰；关键帧保留。淘汰通知解码端重建参考链并请求关键帧，通知限频，不让后续依赖帧无声续播。后台视频仍认证解密，并降低工作线程优先级；未实施未经协议验证的暂停命令或跳过认证。
- 将接收完成的单调时间传到解码端，统计不再从解密之后才开始。分别输出读取、处理统计，解密/排队分位数、接收完成至 codec 输出的年龄分位数、显示/喂入帧增量及恢复次数。分位数使用固定 5ms 桶，超过 2 秒落入饱和桶；这些值仍不包含触控上行、手机处理以及实际屏幕呈现时间。
- Surface/SurfaceTexture 延迟到旧 codec 工作线程实际退出后释放。TextureView 销毁回调交出资源所有权后立即返回，清理在线程后台串行进行；仍不能将活着的旧 codec 所用 Surface 提前释放。已有 generation 检查保留，过期清理任务不会恢复新目标。
- 已有成功出图的活动会话在视频重置、Surface 重建和 Activity 暂停/恢复时保留 CarPlay 页面。连接页面只在有效终止、真实失败、手动断开或新连接生命周期出现；普通错误文本不得抢占活动会话。保留首帧看门狗的局部恢复，不因此重跑 USB/MFi。
- 日志通过 256 项有界 FIFO 后台写入，保留原始发生时间。满队列优先保留关键事件，记录累计丢弃数；关闭排空后才关闭文件。普通模式保留性能摘要、状态和故障，详细模式保留额外协议流量。原始结构化协议记录在格式化前检查详细开关。
- 音频焦点丢失、临时丢失、duck 与恢复接入现有平滑音量控制。回到可见界面时，仅在没有原厂通话/SCO 的条件下尝试重新取得已丢失的焦点，不主动启动或切断 SCO。
- CarPlay telephony 输入与输出共享通信模式租约。仅从正常模式、无 SCO 时切入通信模式；所有使用者结束后，只恢复本会话仍拥有的模式，不重置外部接管后的原厂通话模式。麦克风线程提升至音频优先级。
- 辅助/通话流首选缓冲不再统一乘四或套用音乐的 16384 字节下限，目标约 90ms，仍尊重设备最小缓冲；首选初始化失败时保留旧容量回退。音乐原有 120ms 预填充和约 220ms 容量策略保持。
- 增加被动 HFP/SCO 状态、音频模式、前台组件和页面切换关联记录。不记录联系人、电话号码、音频内容；不拦截原厂程序，不强拉前台覆盖摄像头。
- AUTO 模式只借用已经开启且可用的原厂热点，热点不可用或存在恢复遗留时直接继续有线；不再在普通有线启动时创建热点并触发长时间停止/恢复。显式 Wi-Fi 测试模式保留原有可恢复热点流程。
- 增加可选 960×540 低负载画面，标准模式默认不变。通过“诊断日志 → 画面性能”选择，下次启动应用生效；活动会话和摄像头布局变化不触发重新协商或重连。触控继续按显示区域归一化，协议尺寸、codec 和 Surface 缓冲使用同一选定尺寸。

## 连接页面回退的专项保护

`CrvConnectionPresentation` 分开维护当前目标是否有新输出与本活动会话是否曾成功显示。前者供看门狗判断，后者保护页面，直到正式终止才清除。Activity 的连接提示、错误文案和 showHome 入口都检查该保护；恢复到前台也重新应用视频页面状态。现有 attempt epoch、会话/媒体所有权隔离、USB detach 核验和清理门禁继续保留。

回归覆盖反复 reset、重复 ACTIVE、真实结束、新会话、旧流迟到回调和音频/日志并发退出。自动化测试不能替代 OEM 固件上的实际前台行为验收。

## 尚不能宣称已解决的实车项目

1. **电话/微信被原厂程序抢占**：目前没有经核实的 Honda 私有 HFP/前台仲裁接口。已改善应用侧通信模式、焦点恢复和关联取证，但没有实现未经验证的原厂拦截；不能承诺原生界面不再出现。普通电话、微信通话、微信语音消息需分开验收。
2. **摄像头音质**：已降低日志阻塞与辅助缓冲、保证 Surface 释放顺序、改善音频线程和路由恢复；资源竞争或 OEM 路由切换是否仍有异常，需要实车复验。
3. **解密吞吐**：拆线程改善接收与处理的衔接，不等于密码计算加速。未引入不适用于 API17 视频 AAD 路径的 Conscrypt 替换；持续高码率仍可能触发过期恢复。可选低负载模式必须通过实车画面与触控验收后再考虑改默认。
4. **FramePacer**：按方案暂缓；保持低延迟策略，不增加显示缓冲。
5. **最终 APK 验证**：本轮没有打包，因此未运行最终 DEX、APK 签名与安装验证；后续生成 APK 时仍须执行已有完整门禁。

## 实车验收步骤

- 标准模式连接并出图后，固定音源，分别反复切换普通原厂页面和右转摄像头，观察进入、保持、退出三个阶段；确认没有连接页闪回、爆音、断音、音量或通话音质残留。
- 连续点击、滑动和拖动地图，用外部录像测量反馈延迟；与同一画面、同一音源的旧版本比较。分别测标准与低负载模式，不同时更改音频或日志参数。
- 分别测试电话呼入/呼出、微信语音通话和语音消息；检查前台组件、HFP/SCO、telephony SETUP/TEARDOWN、双向语音和挂断后音乐恢复。
- 验证真实拔线、手动断开、权限撤销会正常结束并显示可操作的连接页面，防止页面保护掩盖真实断线。
- 普通日志与详细日志做相同操作对照；保留异常准确时刻，关注 receive/processing 两个独立窗口，不能将同一包的不同层过期统计相加。
